# Happy Oyster Python Demo Server API Contract


This document is the single public contract entry point for the `/server-api/*` endpoints of this project. External users who want to know "which endpoints the Python demo exposes, when to call them, what the request parameters are, and what the responses are" should look here only.

`/openapi/v1/**` is the upstream open platform / SDK runtime contract, not the default calling entry point of this demo. This demo demonstrates the third-party server path: the server holds the main API Key, while the client receives both credentials needed to enter a Travel—a temporary API Key (`token`) and a one-time Travel `ticket`.

## 1. General Conventions

### 1.1 Local Demo Address

Default local address:

```text
http://127.0.0.1:3000
```

All business endpoints use the `/server-api/*` prefix. The Python demo then calls the Bailian app gateway with the server-side main `DASHSCOPE_API_KEY`.

### 1.2 Authentication

When calling the demo endpoints during local debugging, the client does not need to send `Authorization`. Before starting the Python demo, you must configure the Bailian API Host and the main API Key:

```bash
export BAILIAN_API_HOST='llm-<your-workspace-id>.cn-beijing.maas.aliyuncs.com'
export DASHSCOPE_API_KEY='sk-...'
python3 server.py
```

`BAILIAN_API_HOST` is obtained from the "API Host" field on the API Key page of the Bailian console, for example `llm-<your-workspace-id>.cn-beijing.maas.aliyuncs.com`. This demo completes the fixed gateway path internally as `https://{BAILIAN_API_HOST}/api/v2/apps/happyoyster-1.0`.

The API Host must be used with an API Key from the same account and region; otherwise the gateway may return `AccessDenied` or `401`. API Keys are region-specific and cannot be used across regions.

`DASHSCOPE_API_KEY` must be a main API Key for management and server-only endpoints. Client OpenAPI endpoints that allow temporary Keys are not subject to that restriction.

For production integration, the third-party server must add its own login session, user authorization, tenant isolation, and resource ownership checks on top of `/server-api/*`. Do not expose this demo directly to untrusted clients without business-level authentication.

### 1.3 Response Envelope

Except for the normal response of `POST /server-api/temp-api-key`, all other business endpoints pass through the Bailian app gateway response. Normal business data is located in `output.data`:

```json
{
  "request_id": "xxx",
  "output": {
    "code": 0,
    "message": null,
    "data": {}
  }
}
```

Interpretation rules:

- `output.code == 0`: business success.
- `output.code != 0`: open API business error.
- Top-level string `code`: proxy or gateway-layer error, e.g. `ResponseTimeout`.

Errors generated by the local demo itself are only used for parameter validation, unknown routes, or upstream request failures, for example:

```json
{
  "success": false,
  "errorCode": "UPSTREAM_ERROR",
  "message": "Upstream OpenAPI request failed"
}
```

### 1.4 Common Enums

| Enum          | Values                                                                                       |
| ------------- | -------------------------------------------------------------------------------------------- |
| `mode`        | `1 = adventure`, `2 = directing`                                                                     |
| World status  | `generating` / `ready` / `failed`                                                             |
| Travel status | `init` / `pending` / `running` / `completed` / `failed`; the `pause` response returns `paused` |

`mode` must be a numeric value; do not pass the strings `adventure` / `directing`.

### 1.5 Current User Model

The current demo does not implement the third party's own user system; it demonstrates a single-user / single main API Key scenario: no business user login, user ID mapping, tenant isolation, or secondary resource ownership checks. For production integration, the third-party server needs to add its own user authentication and authorization logic on top of this demo.

When Bailian injects `x-dashscope-workspace`, the open platform isolates Worlds and Travels by `uid + workspace`. Cross-workspace World access is usually handled as `403001`, while Travel access is usually handled as `404000`. Callers must not forge this header. This demo uses one fixed `BAILIAN_API_HOST` / `DASHSCOPE_API_KEY` upstream identity and does not replace the third party's own tenant isolation.

## 2. Endpoint Overview

| #   | Endpoint                  | Method | Path                              | When to call                                     |
| --- | ------------------------- | ------ | --------------------------------- | ------------------------------------------------ |
| 1   | Issue temporary API Key   | POST   | `/server-api/temp-api-key`        | On app startup or when the temporary key is about to expire |
| 2   | Create world              | POST   | `/server-api/worlds`              | Third-party server creates a world                  |
| 3   | Query build status        | GET    | `/server-api/worlds/build-status` | Poll after creating a world                      |
| 4   | Query world detail        | GET    | `/server-api/worlds/detail`       | Confirm the status and details of a single world |
| 5   | Get Travel Ticket     | POST   | `/server-api/travel-credential`   | Exchange for a one-time `ticket` after the world is `ready` |
| 6   | Query world list          | GET    | `/server-api/worlds`              | Backoffice listing, debugging, or resource verification |
| 7   | Query Travel list         | GET    | `/server-api/travels`             | View Travel records on the server side           |
| 8   | Query Travel artifacts    | GET    | `/server-api/travels/artifacts`   | Query artifacts after Travel is `completed`      |
| 9   | ScriptList full update    | POST   | `/server-api/travels/update-script` | Server-side update of 45 turns |
| 10  | Delete world              | POST   | `/server-api/worlds/delete`       | After testing or for business resource cleanup   |

Recommended main flow:

```text
POST /server-api/worlds
  -> GET /server-api/worlds/build-status poll until ready
  -> POST /server-api/temp-api-key
  -> POST /server-api/travel-credential
  -> return both token and ticket to the App / Web client
```

The ticket is valid for 30 minutes and is consumed once by `enter-travel`. Refreshing the temporary API Key does not require exchanging for another ticket.

`async=false` holds the HTTP request for a long time and is not recommended as the main server-side path.

The server owns World creation / management, credential exchange, Travel history and artifacts, and full ScriptList updates. The client SDK owns entering the Travel, RTC / playback, and the remaining runtime controls. To enter, the client authenticates `POST /openapi/v1/travels/enter-travel` with the temporary Key, sends the ticket in the body, and may pass the JSON integer `maxExperienceTimeSec` for Adventure (`60` / `90` / `120`, default `60`; ignored for Directing). It should then read `output.data.noStreamAutoEndTimeoutSec`, poll `/openapi/v1/travels/status`, and report `clientStreamStatus` / `clientStreamStatusTimeMs` as needed. If the streaming state (e.g. `rtcStatus=PUSHING`) is still not observed after the timeout, call `POST /openapi/v1/travels/end` with `failCode=TRAVEL_NO_STREAM_AUTO_END`.

The latest OpenAPI does not support passing `userAgent` via Query on any GET endpoint, and World-related POST bodies do not read `userAgent` either; use the HTTP `User-Agent` header for client identification. Only Travel control POST endpoints may explicitly pass `userAgent` in the body.

## 3. Endpoint Details

### 1. Issue Temporary API Key

`POST /server-api/temp-api-key`

When to call: when you need to let untrusted clients such as browsers or mobile apps call SDK-side endpoints.

Request Query:

| Field               | Type    | Required | Description                                                          |
| ------------------- | ------- | -------- | -------------------------------------------------------------------- |
| `expire_in_seconds` | integer | No       | TTL in seconds, range `1..1800`; if omitted, the Bailian default TTL is used |

Request Body:

| Field               | Type    | Required | Description                              |
| ------------------- | ------- | -------- | ---------------------------------------- |
| `expire_in_seconds` | integer | No       | TTL in seconds, range `1..1800`          |
| `expireInSeconds`   | integer | No       | camelCase alias of `expire_in_seconds`   |

When both Query and Body are present, Query takes precedence.

The normal response is not wrapped in `output`:

```json
{
  "token": "st-****",
  "expires_at": 1744080369
}
```

Local parameter error:

```json
{
  "success": false,
  "errorCode": "PARAM_INVALID",
  "message": "expire_in_seconds must be an integer between 1 and 1800"
}
```

### 2. Create World

`POST /server-api/worlds`

When to call: the third-party server creates a world. It is recommended to pass `async=true` or omit `async`, then poll the build status.

Request Body:

| Field             | Type    | Required    | Description                                                        |
| ----------------- | ------- | ----------- | ------------------------------------------------------------------ |
| `mode`            | integer | Yes         | `1=adventure`, `2=directing`                                              |
| `async`           | boolean | No          | Defaults to `true`; `false` waits synchronously and is easily interrupted by gateway timeouts |
| `creationModel`   | string  | No          | `simple` (default) / `scriptlist`; only effective when `mode=2`    |
| `prompt`          | string  | Conditional | World theme description; required for first_frame / Directing simple, not needed as a top-level prompt for scenario_role |
| `eventStyle`      | string  | No          | `normal` / `dramatic`                                              |
| `refWorldId`      | string  | No          | Encrypted ID of the reference template world                       |
| `perspective`     | string  | Conditional | Required for Adventure: `first_person` / `third_person`               |
| `uploadMode`      | string  | No          | Adventure: `first_frame` / `scenario_role`                            |
| `firstFrameImage` | object  | No          | First-frame image for Adventure first_frame / Directing simple: `{ url or base64, referenceType }`, optional; required for scriptlist |
| `sceneImage`      | object  | No          | Adventure scenario_role: `{ url or base64, referenceType }`                     |
| `roleImage`       | object  | No          | Adventure scenario_role: `{ url or base64, referenceType }`                     |
| `scenePrompt`     | string  | No          | Adventure scene description                                           |
| `rolePrompt`      | string  | No          | Adventure role description                                            |
| `resolution`      | string  | Conditional | Required for Directing: `480p` / `720p`                                |
| `layout`          | string  | No          | Directing: `Stable` / `Fast`                                           |
| `narrative`       | string  | No          | Directing: `Calm` / `Dramatic` / `Normal`                              |
| `inputImages`     | array   | No          | Additional reference images: `[{ url or base64, referenceType }]`       |
| `scriptList`      | object  | Conditional | Required when `creationModel=scriptlist`                           |

Image reference objects `firstFrameImage`, `sceneImage`, `roleImage`, `inputImages[]`, and `scriptList.subjects[].refImage` all use the same structure: `url` is an HTTP(S) image URL, `base64` accepts both raw base64 and a `data:image/xxx;base64,...` data URI, and `referenceType` is optional and defaults to `default`. `url` and `base64` must not both be non-empty in the same object. URL images and decoded base64 images must be JPG/JPEG/PNG/WebP, each strictly smaller than 30 MB, with at most 4096×4096 pixels after decoding. A first-frame image must also be landscape with a width-to-height ratio in the inclusive range `1.5..2.0`; other reference images do not have this ratio requirement.

A `prompt` that is null, an empty string, or whitespace only is treated as missing by the upstream. The default `first_frame` and Directing simple creation must pass a non-empty `prompt`; `scenario_role` does not require a top-level `prompt`, but requires at least one non-empty value among `scenePrompt` / `rolePrompt`, or both `sceneImage` and `roleImage` to be provided, each containing either `url` or `base64`.

`creationModel=scriptlist` is only used for Directing worlds and requires `resolution`, `firstFrameImage` containing either `url` or `base64`, and `scriptList`. It does not accept fields such as `prompt`, `layout`, `narrative`, `inputImages`, `perspective`, `uploadMode`, `sceneImage`, `roleImage`, `scenePrompt`, or `rolePrompt`. Both creation and `update-script` require exactly 45 acts, ordered as continuous, non-duplicate turns 1 through 45.

Complete ScriptList schema: `synopsis` (required on create, max 2,000), `videoTitle` (128), `scene` / `style` / `speed` / `language` (64 each), `setting` (2,000), `soundtrack` (500), `prologue` (1,000), `videoTags` (up to 20, 32 per tag), `subjects` (up to 6), and `acts`. Each subject supports `label` (`[character_1]` through `[character_6]`, auto-assigned when omitted and unique), `name`, `type` (`character` / `animal` / `creature` / `narrator`), `refImage`, `gender`, `position`, `ethnicity`, `age`, `appearance`, and `voice`; name/gender/position/ethnicity/age are limited to 64 characters each, appearance to 500, and voice to 200. Each act supports `turn`, `content`, `cameraType`, `shotSize`, and `cut`; content is required, limited to 2,000 characters per act and 100,000 total, and subject references must match defined labels.

`cameraType`: `Static` / `Tracking` / `Pan Left` / `Pan Right` / `Tilt Up` / `Tilt Down` / `Push-in` / `Pull-out` / `POV Forward` / `POV Look Down` / `POV Look Up` / `POV Turn Left` / `POV Turn Right`, default `Static`. `shotSize`: `Wide` / `Medium` / `Close-up`, default `Medium`. `cut`: `long-take` / `hard-cut` / `cut-in` / `cut-out` / `cutaway` / `cutback` / `camera movement transition`, default `long-take`.

The upstream consistently returns parameter errors in an HTTP `200` OpenAPI business envelope. A `Content-Type` other than `application/json`, malformed JSON, invalid fields or enums, image objects that pass both `url` and `base64`, empty or undecodable base64, image size / pixel / ratio violations, and invalid non-HTTP(S) image URLs all return `output.code=400000`. This demo passes that upstream response through.

Response `output.data`:

| Field              | Type        | Description                                                    |
| ------------------ | ----------- | -------------------------------------------------------------- |
| `encryptedWorldId` | string      | Encrypted world ID, used for subsequent queries and credential exchange |
| `status`           | string      | `generating` / `ready` / `failed`                              |
| `firstFrame`       | string/null | First-frame image URL                                          |

### 5. Get Travel Ticket

`POST /server-api/travel-credential`

When to call: after the world is `ready`. If the world is not `ready`, `403002` is usually returned.

Request Body:

| Field              | Type   | Required | Description        |
| ------------------ | ------ | -------- | ------------------ |
| `encryptedWorldId` | string | Yes      | Encrypted world ID |

Response `output.data`:

| Field              | Type    | Description                                                                  |
| ------------------ | ------- | ----------------------------------------------------------------------------- |
| `ticket`           | string  | One-time Travel ticket, returned to the App / Web client for `enter-travel` |

After the client starts the Travel, if no stream is received within `noStreamAutoEndTimeoutSec` seconds, it should call `/openapi/v1/travels/end` with `failCode=TRAVEL_NO_STREAM_AUTO_END`.

### 9. ScriptList Full Update

`POST /server-api/travels/update-script`

When to call: while a Directing ScriptList Travel is in an updatable state, fully replace the remaining script acts for the current Travel.

Request Body:

| Field               | Type   | Required | Description |
| ------------------- | ------ | -------- | ----------- |
| `encryptedTravelId` | string | Yes      | Encrypted Travel ID |
| `scriptList`        | object | Yes      | Full script container; same schema as creation, while only `acts` is consumed by this update |
| `scriptList.acts`   | array  | Yes      | Must contain exactly 45 items, with continuous turns 1 through 45 and no duplicates |
| `userAgent`         | string | No       | Client identifier for Travel control calls; takes precedence over HTTP `User-Agent` |

`update-script` only fully replaces acts. `subjects` and world-level fields in the request `scriptList` such as `synopsis`, `scene`, and `style` are ignored by the upstream, which keeps the ScriptList stored at world creation time. Act length limits and the `cameraType` / `shotSize` / `cut` enums match the complete schema above. Script worlds with `creationModel=scriptlist` do not support incremental text `instruct` calls and keep the error code `403006 INSTRUCT_NOT_ALLOWED`.

Response `output.data`:

| Field               | Type    | Description |
| ------------------- | ------- | ----------- |
| `encryptedTravelId` | string  | Encrypted Travel ID |
| `accepted`          | boolean | Whether the update was accepted into the processing queue |
| `turnCount`         | integer | Number of turns in this update, fixed at `45` |

Common business errors: `400000` (acts not 45 items, duplicate/out-of-range turns, invalid enum, etc.), `403004` (script content moderation rejected), `404000` (Travel missing or no active processor), `409000` (Travel state is not updatable), and `500000` (downstream processing failure).

## 4. Common Errors

| Error                              | Source                | Description                                                       |
| ---------------------------------- | --------------------- | ----------------------------------------------------------------- |
| `BAILIAN_API_HOST is required` | Python demo             | The Bailian API Host was not configured before startup |
| `DASHSCOPE_API_KEY is required`    | Python demo             | The main API Key was not configured before startup                |
| `PARAM_INVALID`                    | Python demo / open API  | Invalid parameter                                                 |
| `403002`                           | Open API              | The world is not ready; the Travel ticket cannot be exchanged |
| `403003`                           | Open API              | A management or server-only endpoint was called without the main API Key |
| `ResponseTimeout`                  | Gateway               | Downstream response timeout, common with `async=false`            |
| `UPSTREAM_ERROR`                   | Python demo             | Python demo failed to request the upstream or timed out locally     |
